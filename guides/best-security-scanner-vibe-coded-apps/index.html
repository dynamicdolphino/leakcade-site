Short answer: which security scanner for vibe coded apps?

Start with the free scans that already come with your tools, then add one outside view. For a typical Lovable, Bolt or Cursor app on Supabase that means:

  1. Your builder's own scan: the Lovable Quick and Deep scan or Bolt security audit.
  2. The Supabase Security Advisor on your live database.
  3. A secret scan over the whole git history, with GitHub secret scanning (free on public repos) or gitleaks.
  4. One check from outside: the ZAP baseline scan or a hosted URL scanner, plus a test with two accounts.

Pay for a hosted scanner when you want one report across several layers, scheduled re-scans or fix prompts. Pick it by what it reads.

Four places a scanner can look

Vibe coding security tools are hard to compare because they read different things. A scanner can look at four places:

  • The live site: the JavaScript bundle, headers, cookies and files like /.env. URL scanners look here.
  • The code: routes, server actions, Edge Functions, SQL built from strings. Repo scans and builder code reviews look here.
  • The git history: keys you pasted and deleted are still in old commits. Only tools that read commits see them.
  • The live database rules: policies set in the Supabase dashboard, which can differ from your migrations. The Security Advisor and builder scans look here.

Free scans built into Lovable, Bolt and Supabase

  • Lovable security scan. The Quick scan runs every time you publish and reviews database access rules, known critical vulnerabilities in npm packages and an MCP server exposed without a login. The Deep scan reviews your app code for access control, open endpoints, injection, leaked secrets, payments and sign-in, but only when you start it. Running both is free. Lovable's docs say the tools "cannot guarantee complete security". See Lovable security scan vs Leakcade.
  • Bolt security audit. The project audit reviews code and database, fixes what it can and lists what you must change yourself. It's on paid plans, doesn't use tokens when you start it from the Publish menu, and is capped at 30 audits a day. A lighter database check runs on all plans. See Bolt app security.
  • Supabase Security Advisor. Deterministic checks on your live project, run from Studio, the CLI (supabase db advisors) or MCP. It flags tables with RLS off, policies with USING (true), views that skip RLS and security definer functions anyone can call. Supabase warns that some findings may be intentional.

These three see your real configuration. None of them looks at the live site the way a stranger does, and the tool that built the app is also the one checking it.

Free open source and GitHub tools

  • GitHub secret scanning. On public repos it runs automatically and for free, across the entire git history on all branches. On private repos it's part of a paid add-on. GitHub's advice when it finds a key: rotate it right away.
  • gitleaks. MIT-licensed CLI. gitleaks git scans every patch through git log -p, and gitleaks dir scans files. Our guide to finding secrets in git history has the commands.
  • Semgrep. Static analysis for injection, XSS sinks and risky APIs. The CLI runs on your machine, and Semgrep's docs say code is not uploaded, only findings.
  • ZAP baseline scan. Spiders your site for a minute, then reports what passive checks found: missing headers, cookie flags, error pages. ZAP's docs say it doesn't perform any actual attacks. It knows nothing about Supabase.

Hosted scanners made for AI-built apps

  • Aikido. Connects to your GitHub repos and scans code, packages and secrets. The free Developer plan covers 10 repos, 2 users, 1 domain for its DAST scan and 10 AI AutoFixes a month, with rescans every 3 days.
  • CheckVibe. Scans the live site in a real browser, a connected repo and, on paid plans, a connected Supabase project's tables, policies and buckets. Starter is $24 a month, Pro $49 with daily monitoring, and every plan starts with a 14-day trial. A free account scans your site and code but masks part of each findings list.
  • Vibe App Scanner. Your first URL preview is free and shows a score, counts and one finding. Go is $29 a month (20 live-app scans, 10 repo scans), Pro $49 with weekly monitoring. Repo scans need a paid plan.
  • SniffPup. A passive scan of your published URL, including whether an anonymous visitor can read rows in a few Supabase tables. The scan is free, a one-time Full Fix Report is $9, and plans with daily re-scans start at $7 a month. The full check of a public GitHub repo is in the paid plans.
  • Leakcade (us). Reads a public GitHub repo as text: gitleaks over the files and the last 50 commits, Semgrep, OSV-Scanner, a check for made-up package names, our Supabase migration checks, and an AI review in the paid report. The free teaser shows a score, counts and one redacted finding. The full report is $19 one time, and we're pre-launch.

What no scanner catches on its own

The most useful public test we found is BuildWithThis's, run on Oct 16, 2026. They planted 10 holes in one small Supabase app and ran six tools. The best single tool caught 4.5 of the 10, and all six together caught 7.5. None of the six flagged a policy that let any signed-in user read and edit every profile, or an Edge Function with no login check. It was one small test app, so read the numbers as a rough signal.

A policy that only checks that someone is logged in passed every tool in that test, because the rule exists and RLS is on. A second account finds it:

Prompt: what did my scanners miss?

Paste this into Cursor, Claude Code or your builder's chat after the scans. It asks for the gaps the tools above can't see.

GAP PROMPT
I ran these security scans on this app: [list them]. Using the code in
this repo, list what those scans could not see:
1) every Supabase policy that only checks for a login instead of the row
   owner (auth.uid() = owner column), for select, update and delete
2) every Edge Function, API route and server action that changes data
   without checking who is calling
3) every key or secret that ever appeared in code or git history
4) settings that live outside the repo (dashboard policies, buckets,
   headers) that I must check on the live project
Give file and line for each, and the smallest fix first.

FAQ

Is there a free security scanner for vibe coded apps?

Yes. Lovable's scans are free to run, Bolt's database check is on all plans, the Supabase Security Advisor is built into the dashboard, and gitleaks, Semgrep's CLI and ZAP cost nothing. GitHub secret scanning is free on public repos.

What is the best security scanner for a Lovable or Bolt app?

Start with the builder's own scan and the Supabase Security Advisor, because they see your real database settings. Then add a git history secret scan and one check of the live site from outside, and test with a second account.

Can one scanner tell me my app is secure?

No. In BuildWithThis's Oct 16, 2026 test of six tools on one app with 10 planted holes, the best tool caught 4.5 and all six together caught 7.5. A clean scan means the tool found nothing with the checks it ran.
